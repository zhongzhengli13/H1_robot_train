## 二、问题一：姿态难看

### 现象
- 步态看起来扭曲、不自然
- Yaw 角在整个 episode 内持续积累，末端偏转约 17.7°
- 左右腿运动模式明显不同

### 根本原因

**1. 对称奖励权重不足或冲突**

代码中存在 `symmetry` 奖励，但其权重（2.0）相对于速度奖励（`fwd_vel_rew` × 5.5、`lateral_vel_rew` × 6.0）过低。网络为了最大化速度奖励，宁愿牺牲对称性。

**关键数据：**
```
关节             左腿均值     右腿均值     差异
hip_yaw:         0.040        -0.062       0.102 rad  ← 严重
hip_pitch:       -0.057       -0.126       0.170 rad  ← 严重
knee:            0.317        0.532        0.262 rad  ← 极严重
```

**2. `balance_rew` 乘数导致奖励"绑架"**

当前设计中，大多数奖励都乘以 `balance_rew`：
```python
fwd_vel_rew  *= balance_rew  # weight 5.5
yaw_rate_rew *= balance_rew  # weight 4.0
```
这使得任何能维持平衡的姿势都能获得高分，即便姿态很丑陋。Policy 发现了一个"高收益捷径"：用不对称的腿来平衡，再让yaw持续偏转来补偿。

**3. 躯干俯仰姿态缺乏直接惩罚**

debug 数据显示 `pitch = 0.0057 rad`（正常），但 roll/pitch 的惩罚（`twist_rew`）权重仅 2.5，且只在 `euler[0:2]` 偏大时起作用。对"微微驼背"或"轻微身体前倾"的小角度没有足够约束。

### 建议调整方向

1. **大幅提升对称奖励权重**（从 2.0 提升到 5.0～8.0），与速度奖励量级对齐
2. **解耦 balance_rew 乘数**：对称奖励不应依赖 `balance_rew`，因为不对称本身就是一种"不良平衡"
3. **增加姿态基准惩罚**：对髋关节 yaw 偏离零位进行直接线性惩罚（独立于 balance_rew）

## 三、问题二：一条腿抬脚偏低

### 现象
- 左右腿抬腿高度不一致，某一腿在摆动相明显偏低
- 视觉上显得"跛行"

### 根本原因

**1. 膝关节极度不对称导致有效摆动高度不同**

```
knee_left  均值: 0.317 rad
knee_right 均值: 0.532 rad  ← 右膝更弯
```

右膝更弯意味着右腿质心更低，摆动时脚离地高度取决于髋部抬高量减去膝弯曲量。如果右膝总是更弯，即使髋部抬高相同，右脚净离地高度也会更低。

**2. 接触时间不对称导致步态相位不匹配**

```
左脚接触占比: 54.1%
右脚接触占比: 43.0%
```

右腿在支撑相更短，摆动更快但幅度可能更小。`foot_clear_rew` 依赖于相位 mask，如果相位判断和实际接触脱节，奖励信号就会失效。

**3. `foot_height_rew` 设计问题**

当前 `foot_height_rew` 惩罚的是"摆动超高"，不直接奖励"达到目标高度"。若一条腿抬高不够，这个奖励无法提供正向激励——它只惩罚过高，而不奖励足够高。

### 建议调整方向

1. **增加最小抬脚高度奖励**：
   ```
   min_clearance_rew = clamp(foot_height - min_threshold, 0, ∞)
   ```
   对摆动相内脚高未达到阈值（如 0.05 m）的情况给予负奖励

2. **对步态相位的左右差异进行惩罚**：
   惩罚 `|contact_time_left - contact_time_right|`，强制左右腿支撑时间对称

3. **对称奖励覆盖膝关节**：确认 `symmetry` 奖励包含膝关节（`knee_l` 与 `knee_r`），且权重足够强

## 四、问题三：直线行走差

### 现象
- 前进 8.76 m 的同时侧移 -1.92 m（漂移率 22%）
- Yaw 方向累计偏转约 17.7°
- 这与 try_x2 中的 22.6% 漂移几乎没有改善

### 根本原因

**1. 三项修复中只有两项真正生效**

| 修复项 | 是否生效 | 效果 |
|--------|---------|------|
| 观测中加入侧向速度 `vy` | ✓ 已应用 | 网络能感知侧漂 |
| Yaw 角速度线性惩罚（系数5.0） | ✓ 已应用 | Yaw 漂移减少 45% |
| 左右对称奖励 | ⚠️ 形式上存在，权重不足 | 腿部不对称**更严重** |

真正导致侧漂的是腿部不对称产生的**内在转矩**：左腿接触更多 → 右腿推力更大 → 机器人自然向左偏转 → 积累为侧向漂移。单靠惩罚 yaw 角速度无法消除这个物理根源。

**2. Yaw 惩罚形式仍以指数为主**

```python
yaw_rate_rew = exp(-k * (cmd_yaw - actual_yaw_rate)²) * balance_rew * 4.0
yaw_rate_rew -= 5.0 * |base_ang_vel[2]| * static_flag  # 线性补充
```

当 yaw_rate = 0.016 rad/s 时，指数项 ≈ 0.9997（几乎满分）。线性项只在接近静止（`static_flag=1`）时生效。动态行走中，yaw 偏转基本不被惩罚。

**3. 位置漂移本身没有被惩罚**

目前惩罚的是速度（`lateral_vel_rew`）和角速度（`yaw_rate_rew`），但不惩罚**累积位置偏移**。即便每步侧漂很小，经过 1000 步就会积累到 2m 的偏差。

### 建议调整方向

1. **增强线性惩罚**，不依赖 `static_flag`：
   ```python
   yaw_rate_rew -= 8.0 * abs(base_ang_vel[2])  # 去掉静止约束
   lateral_vel_rew -= 5.0 * abs(base_lin_vel[1])  # 已有3.0，可加强
   ```

2. **Heading 误差奖励**：
   ```python
   heading_err = angle_between(robot_forward, target_direction)
   heading_rew = -heading_err * weight  # 直接惩罚朝向偏离
   ```
   这是最直接的直线行走奖励，比间接惩罚 yaw 速度更有效。

3. **根本修复：强制腿部对称**（参见问题一和问题二的建议）：
   对称的腿不产生内在转矩 → 自然直线行走

4. **考虑引入 episode 内位置约束**（可选）：
   ```python
   lateral_pos_rew = -abs(base_pos[1] - initial_pos[1]) * weight
   ```
   对超过阈值（如 0.1 m）的累积侧偏给予惩罚

## 五、优先级建议

按照解决问题的性价比排序：

### 高优先级（预期效果大，改动小）

**A. 大幅增加对称奖励权重**
- 修改位置：`locomotion_task.py` 中 `symmetry` 奖励权重
- 当前值：`2.0`
- 建议值：`6.0 ~ 8.0`
- 预期效果：同时改善姿态、抬腿不对称、直线行走

**B. 对 Yaw 角速度去掉 static_flag 限制**
- 修改位置：`yaw_rate_rew -= 5.0 * abs(ang_vel[2]) * static_flag`
- 建议：去掉 `* static_flag`，在所有步态状态下惩罚 yaw 偏转

**C. 增加最小抬脚高度奖励**
- 在摆动相内，若脚高 < 阈值（如 0.04 m），给予负奖励
- 直接解决"一条腿抬脚低"问题

### 中优先级（需要更多实验验证）

**D. 增加 heading 误差惩罚**
- 在观测中引入当前朝向与目标方向的夹角
- 直接监督直线行走目标

**E. 增加接触时间对称惩罚**
- 惩罚 `|contact_fraction_L - contact_fraction_R|`
- 从步态结构层面强制对称

### 低优先级（效果不确定）

**F. 累积侧向位置惩罚**
- 可能导致训练不稳定，建议仅在 A-C 效果不足时尝试

## 六、快速验证方案

在实施上述修改前，建议先做单一变量验证：

1. **只改对称权重（A）**，训练 500 iter，观察膝关节不对称是否下降
2. **只改 Yaw 惩罚（B）**，训练 500 iter，观察漂移是否改善
3. 若两者均改善，再合并训练到收敛

每次 debug 时重点观察 Excel 中的：
- `knee_left` vs `knee_right` 均值差
- 最终 `base_pos[1]`（侧向位移）
- `yaw_rate` 均值
