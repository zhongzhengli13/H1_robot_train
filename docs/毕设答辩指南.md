## 二、前置知识点补充

### 2.1 什么是强化学习 (RL)？

强化学习是机器学习的一个分支，核心思想是 **"试错学习"**：

```
智能体(Agent) 在 环境(Environment) 中采取 动作(Action)
    → 环境返回 新状态(State) 和 奖励(Reward)
    → 智能体根据奖励调整策略，最大化累计奖励
```

用本项目举例：
- **智能体** = 策略神经网络（Actor）
- **环境** = Isaac Gym 仿真器中的 H1 机器人
- **状态（观测）** = 机器人当前的关节角度、角速度、身体姿态等（共 38 维）
- **动作** = 12 维向量（2 维步态频率 + 10 维关节增量）
- **奖励** = 走得快、走得稳、不摔倒 → 正奖励；摔倒、乱动 → 负奖励

### 2.2 什么是 PPO？

PPO (Proximal Policy Optimization，近端策略优化) 是 OpenAI 提出的 RL 算法，是目前最流行的策略梯度方法之一。

**核心思想**：每次更新策略时，不让新策略偏离旧策略太远（用 clip 限制），保证训练稳定。

**PPO 的三个关键损失函数**：

```
总损失 = 策略损失(Surrogate Loss) + 价值损失(Value Loss) - 熵奖励(Entropy Bonus)
```

1. **策略损失 (Surrogate Loss)**：
   ```
   L_clip = -E[min(r_t * A_t, clip(r_t, 1-ε, 1+ε) * A_t)]
   ```
   - `r_t = π_new(a|s) / π_old(a|s)` — 新旧策略的概率比
   - `A_t` — 优势函数（衡量这个动作比平均水平好多少）
   - `ε = 0.2` — clip 范围，防止策略更新太大

2. **价值损失 (Value Loss)**：
   ```
   L_value = (V(s) - R)^2
   ```
   - `V(s)` — Critic 网络对状态价值的估计
   - `R` — 实际累计回报

3. **熵奖励 (Entropy Bonus)**：
   ```
   H = -E[log π(a|s)]
   ```
   - 鼓励探索，防止策略过早收敛到局部最优

### 2.3 什么是 Actor-Critic？

Actor-Critic 是 RL 中的一种架构，包含两个网络：

```
Actor（演员）：输入状态 → 输出动作（"做什么"）
Critic（评论家）：输入状态 → 输出状态价值（"这个状态有多好"）
```

在本项目中：
- **Actor**：输入 38 维观测 → 输出 12 维动作（均值 μ），外加可学习的标准差 σ
- **Critic**：输入 critic 观测 → 输出标量 V(s)

### 2.4 什么是 PD 控制器？

PD (Proportional-Derivative) 控制器是机器人控制中最基础的控制器：

```
力矩 τ = Kp × (目标位置 - 实际位置) - Kd × 实际速度
```

- `Kp`（刚度/比例增益）：位置误差越大，力矩越大 → "弹簧"
- `Kd`（阻尼/微分增益）：速度越快，阻力越大 → "阻尼器"

对应代码 [legged_robot.py:684-687](env/legged_robot.py#L684-L687)：
```python
torques = (
    self.p_gains * self.p_gains_rand * error      # Kp × 位置误差
    - self.d_gains * self.d_gains_rand * self.joint_vel  # - Kd × 速度
)
```

**类比**：PD 控制器就像一个"弹簧+阻尼器"系统。目标位置是弹簧的自然长度，Kp 是弹簧刚度，Kd 是阻尼系数。

### 2.5 什么是 Isaac Gym？

Isaac Gym 是 NVIDIA 开发的 GPU 加速物理仿真平台，核心特点：
- **GPU 并行**：同时仿真数千个环境（本项目用 4096 个）
- **PhysX 后端**：使用 NVIDIA PhysX 物理引擎
- **Tensor API**：所有状态数据都是 PyTorch tensor，可以直接在 GPU 上运算

### 2.6 什么是四元数 (Quaternion)？

四元数是表示三维旋转的一种方式，比欧拉角（Roll/Pitch/Yaw）更稳定，不会出现万向锁问题。

四元数 `q = (x, y, z, w)`，其中：
- `(x, y, z)` — 旋转轴 × sin(θ/2)
- `w` — cos(θ/2)

在本项目中，机器人的朝向用四元数表示，观测中使用欧拉角（Roll, Pitch）是因为更直观。

### 2.7 什么是 URDF？

URDF (Unified Robot Description Format) 是描述机器人模型的 XML 格式文件，包含：
- 连杆（link）：机器人的各个部件（大腿、小腿、脚等）
- 关节（joint）：连杆之间的连接方式（旋转、固定等）
- 碰撞/视觉几何体：用于物理仿真和渲染

H1 机器人有 19 个自由度（DOF）：
```
左腿(5): hip_yaw, hip_roll, hip_pitch, knee, ankle
右腿(5): hip_yaw, hip_roll, hip_pitch, knee, ankle
躯干(1): torso
左臂(4): shoulder_pitch, shoulder_roll, shoulder_yaw, elbow
右臂(4): shoulder_pitch, shoulder_roll, shoulder_yaw, elbow
```

### 3.2 单步数据流详解

一帧（step）的完整数据流：

```
Step 1: 观测生成
  LocomotionTask.pure_observation()
  → 38维向量：[命令(2), 角速度误差(1), 姿态(2), 角速度(3),
              关节位置误差(10), 关节速度(10), 关节目标误差(10)]

Step 2: 策略推理
  Actor(obs) → net_out (12维, 范围[-1, 1])
  scale_transform → 缩放到 [action_low, action_high]
  → 前2维: 步态频率 [0.5, 3.5] Hz
  → 后10维: 关节速度增量 [-12, 12] rad/s

Step 3: 动作执行
  LocomotionTask.action(net_out)
  → 相位调制器更新: phase += 2π × freq × dt
  → 关节目标 = 当前关节位置 + 增量 × dt
  → clip 到关节安全范围

Step 4: 物理仿真 (decimation=10次)
  for _ in range(10):
    LeggedRobotEnv.step_torques(joint_act)
    → PD控制器: τ = Kp×(目标-实际) - Kd×速度
    → PhysX仿真一步
    → 刷新所有状态

Step 5: 奖励计算
  LocomotionTask.reward()
  → 25+个奖励项求和

Step 6: 终止判断
  LocomotionTask.terminate()
  → 摔倒？关节超限？超时？
```

### 4.2 环境包装器：GymEnvWrapper

[gym_env_wrapper.py:48-69](env/gym_env_wrapper.py#L48-L69) 是连接任务和仿真的桥梁：

```python
def step(self, net_out, step_num):
    # 1. 网络输出 → 关节目标位置
    joint_act = self.task.action(net_out, step_num)

    # 2. PD控制 + 物理仿真（decimation=10次）
    for _ in range(self.env.cfg.pd_gains.decimation):
        self.env.step_torques(joint_act)

    # 3. 更新状态
    self.env.step_states(self.task.commands)
    self.task.step()

    # 4. 生成观测、奖励、终止信号
    obs, estimation_value = self.task.observation()
    rew = self.task.reward()
    done, time_done = self.task.terminate()

    # 5. 重置摔倒的环境
    reset_env_ids = (done > 0).nonzero(...)
    if len(reset_env_ids) > 0:
        self.task.reset(reset_env_ids)
        self.env.reset(reset_env_ids, reset_phy_ids)

    return obs, cri_obs, rew_buf, done, info, ...
```

**decimation 的意义**：策略频率 = 1/(decimation × dt) = 1/(10×0.001) = 100 Hz。物理仿真以 1000 Hz 运行，但策略每 10 步才决策一次，中间 PD 控制器保持目标不变。

### 4.3 核心任务：LocomotionTask

#### 4.3.1 观测设计

[pure_observation()](env/tasks/locomotion_task.py#L575-L601) 构造 38 维观测：

```python
self.obs_buf = torch.cat([
    self.commands[:, [0, 2]],                        # 0-1: 速度指令(vx, yaw_rate)
    (self.commands[:, [2]] - self.base_ang_vel[:, [2]]) * 0.5,  # 2: 偏航角速度误差
    self.base_euler[:, :2] * 3.0,                    # 3-4: Roll, Pitch (×3放大)
    self.base_ang_vel * 0.5,                         # 5-7: 角速度 (×0.5缩小)
    (self.joint_pos[:, :10] - self.ref_joint_action[:, :10]),  # 8-17: 关节位置偏差
    self.joint_vel[:, :10] * 0.1,                    # 18-27: 关节速度 (×0.1缩小)
    twh_joint_pos_error[:, :10],                     # 28-37: 关节目标误差
    pm_phase * self.static_flag,                     # 步态相位(sin,cos)
    (self.pm_f * 0.3 - 1.0) * self.static_flag,     # 步态频率
], dim=1)
```

**设计要点**：
- **缩放 (Scaling)**：不同量纲的物理量需要缩放到相近范围，便于网络学习
- **指令误差**：`命令 - 实际` 比直接给命令和实际更高效，网络直接学习"偏差"
- **相位编码**：用 sin(φ) 和 cos(φ) 而不是原始相位 φ，因为 sin/cos 是连续的（φ=0 和 φ=2π 时 sin/cos 相近，但原始值差 2π）

#### 4.3.2 动作设计

[action()](env/tasks/locomotion_task.py#L618-L644) 将网络输出转为关节目标：

```python
def action(self, net_out, step_num):
    # 1. 缩放：[-1,1] → [action_low, action_high]
    net_out = scale_transform(net_out, self.action_low[:12], self.action_high[:12])

    # 2. 更新步态相位
    self.phase_modulator.compute(net_out[:, :self.num_legs])  # 前2维→频率

    # 3. 增量式控制：新目标 = 旧目标 + 增量 × dt
    act = self.current_joint_act[:, :10] + net_out[:, self.num_legs:] * self.env.dt

    # 4. 安全裁剪
    act = torch.clip(act, self.joint_action_limit_low[:, :10],
                              self.joint_action_limit_high[:, :10])
    return act
```

**增量式控制 vs 绝对控制**：
- **绝对控制**：网络直接输出关节角度 → 容易跳变，训练不稳定
- **增量控制**（本项目）：网络输出"变化量"，累积到当前位置 → 动作平滑，训练更稳定

**scale_transform 函数** ([math.py:63-66](env/utils/math.py#L63-L66))：
```python
def scale_transform(action, action_low, action_high):
    action = torch.clip(action, -1., 1.)  # 先clip到[-1,1]
    action = (action + 1.) / 2. * (action_high - action_low) + action_low  # 线性映射
    return action
```
将 Actor 输出的 [-1, 1] 范围线性映射到实际物理范围。

#### 4.3.3 奖励设计

[reward()](env/tasks/locomotion_task.py#L738-L1339) 是整个项目最复杂的部分，包含 25+ 个奖励项。按功能分类：

**A. 速度跟踪奖励（核心）**

```python
# 前进速度跟踪
forward_vel_rew = exp(-k * (cmd_vx - real_vx)²) × balance_rew

# 侧向速度惩罚（防止横移）
lateral_vel_rew = exp(-k * vy²) - 3.0 × |vy|

# 偏航角速度跟踪
yaw_rate_rew = exp(-k * (cmd_yaw - real_yaw)²) - 8.0 × |yaw_rate|
```

**设计思想**：用高斯函数 exp(-k×e²) 作为奖励，误差越大衰减越快。乘以 `balance_rew` 意味着"只有站稳了，速度跟踪才有意义"。

**B. 平衡奖励**

```python
base_heit_rew = exp(-60 × (height - 1.0)²)  # 保持1m身高

balance_rew = 0.5 × (base_heit_rew × exp(-k × ||姿态角||) + 1.0)
```

**C. 步态质量奖励**

```python
# 抬脚奖励：摆动相时脚应该离地
foot_clear_rew = Σ(swing_foot ∩ phase_swing) / num_legs

# 支撑奖励：支撑相时脚应该着地受力
foot_support_rew = Σ(support_foot ∩ phase_support) / num_legs

# 步态相位对称：左右脚相位差应为 π（反相步态）
foot_phase_rew = -||sin(φL) + sin(φR)||² - ||cos(φL) + cos(φR)||²
```

**D. 平滑性惩罚**

```python
# 动作平滑（二阶差分）
action_smooth_rew = -||act[t-2] - 2×act[t-1] + act[t]||

# 网络输出平滑
net_out_smooth_rew = -||out[t-2] - 2×out[t-1] + out[t]||²
```

**二阶差分的意义**：一阶差分 penalizes 速度变化（加速度），二阶差分 penalizes 加速度变化（jerk）。二阶差分惩罚更能让动作"丝滑"。

**E. 对称性奖励（治瘸腿）**

```python
# 关节力矩对称
tau_symmetry_rew = -||左腿力矩 - 右腿力矩||

# 步幅对称
stride_symmetry_rew = -8.0 × |左步幅 - 右步幅|

# 关节角度对称
joint_symmetry_rew = -2.0 × |左髋pitch - 右髋pitch|
```

**F. 最终奖励汇总**

所有奖励项乘以 `balance_rew`（站稳是前提），再乘以各自权重，clip 到 [-4, 5] 范围，乘以 dt（时间步长），最后求和。

### 4.4 策略网络：Actor-Critic

#### Actor 网络

[continuous.py:9-38](rl/module/continuous.py#L9-L38)：

```python
class Actor(nn.Module):
    def __init__(self, num_observations, num_actions, hidden_layers, activation):
        self.preprocess = Net(input_dim, 0, hidden_layers, activation)  # MLP
        self.mu = nn.Linear(hidden_layers[-1], output_dim)              # 输出层
        self.std = nn.Parameter(torch.ones(output_dim) * 1.)           # 可学习标准差

    def forward(self, s):
        net_out = self.preprocess(s)           # MLP特征提取
        mu = torch.tanh(self.mu(net_out))      # 输出均值，tanh限制到[-1,1]
        dist = Normal(mu, self.std)            # 构建正态分布
        return {'dist': dist, 'act': dist.sample()}  # 采样动作
```

**关键设计**：
- `mu = torch.tanh(...)`：输出范围 [-1, 1]，之后通过 scale_transform 映射到物理范围
- `self.std` 是可学习参数（不是网络输出），初始值 1.0，训练过程中自动调整探索程度
- 训练时从分布中采样（探索），推理时直接用均值（确定性）

#### Critic 网络

[continuous.py:41-53](rl/module/continuous.py#L41-L53)：

```python
class Critic(nn.Module):
    def __init__(self, num_critic_obs, hidden_layers, activation):
        self.preprocess = Net(input_dim, 0, hidden_layers, activation)
        self.value = nn.Linear(hidden_layers[-1], 1)  # 输出标量

    def forward(self, s):
        return self.value(self.preprocess(s))  # V(s)
```

#### MLP 基础模块

[common.py:9-39](rl/module/common.py#L9-L39)：

```python
class Net(nn.Module):
    def __init__(self, input_dim, output_dim, hidden_layers, activation):
        net = []
        dim0 = input_dim
        for dim1 in hidden_layers:
            net.append(nn.Linear(dim0, dim1))  # 全连接层
            net.append(get_activation(activation))  # 激活函数
            dim0 = dim1
        self.net = nn.Sequential(*net)
```

本项目配置：`hidden_layers = (512, 256)`，`activation = "relu"`

Actor: `38 → 512 → ReLU → 256 → ReLU → 12 (tanh)`
Critic: `38 → 512 → ReLU → 256 → ReLU → 1`

### 4.5 PPO 算法实现

[ppo.py](rl/alg/ppo.py) 的核心逻辑：

#### 收集阶段 (act + process_env_step)

```python
def act(self, obs, cri_obs, obs_real, estimation_value):
    res = self.actor(obs)                    # Actor推理
    actions, dist = res['act'].detach(), res['dist']
    self.transition.actions_log_prob = dist.log_prob(actions).sum(dim=-1).detach()
    self.transition.values = self.critic(cri_obs).detach()  # Critic估值
    return actions
```

#### 更新阶段 (update)

```python
def update(self):
    for obs_batch, ... in generator:  # mini-batch训练
        # 1. 重新计算当前策略的动作概率
        dist = self.actor(obs_batch)['dist']
        logp_batch = dist.log_prob(actions_batch).sum(dim=-1)

        # 2. 自适应学习率（基于KL散度）
        kl = ...  # 计算新旧策略的KL散度
        if kl_mean > desired_kl * 2.0:
            learning_rate /= 1.5  # KL太大→降低学习率
        elif kl_mean < desired_kl / 2.0:
            learning_rate *= 1.5  # KL太小→提高学习率

        # 3. 策略损失（PPO-Clip）
        ratio = (logp_batch - old_logp_batch).exp()
        surr1 = ratio * advantages
        surr2 = torch.clamp(ratio, 1-ε, 1+ε) * advantages
        surrogate_loss = -torch.min(surr1, surr2).mean()

        # 4. 价值损失
        value_loss = max((V-R)², (V_clipped-R)²).mean()

        # 5. 总损失 = 策略损失 + 价值系数×价值损失 - 熵系数×熵
        loss = surrogate_loss + 1.0 * value_loss - 0.001 * entropy

        # 6. 梯度下降
        loss.backward()
        clip_grad_norm_(params, max_grad_norm=1.0)
        optimizer.step()
```

#### GAE (广义优势估计)

[rollout_storage.py:63-77](rl/storage/rollout_storage.py#L63-L77)：

```python
def compute_returns(self, last_values, gamma, gae_lambda):
    gae = 0
    for step in reversed(range(num_steps)):
        delta = rewards[step] + gamma * next_values - values[step]  # TD误差
        gae = delta + gamma * gae_lambda * gae  # 累积折扣
        returns[step] = gae + values[step]
    advantages = returns - values
    advantages = (advantages - advantages.mean()) / (advantages.std() + 1e-5)  # 归一化
```

**GAE 的作用**：平衡偏差(bias)和方差(variance)。`λ=0` 时类似 TD(0)（低方差高偏差），`λ=1` 时类似 Monte Carlo（高方差低偏差）。`λ=0.95` 是常用折中。

### 4.6 步态相位调制器

[phase_modulator.py](env/utils/phase_modulator.py)：

```python
class PhaseModulator:
    def compute(self, frequency):
        self._frequency = frequency           # 频率由策略网络输出
        self._phase = (self._phase + 2π × frequency × dt) % 2π  # 相位累加
        return self._phase
```

**相位的含义**：
- `φ ∈ [0, π)` → 支撑相（stance phase）：脚着地承重
- `φ ∈ [π, 2π)` → 摆动相（swing phase）：脚离地迈步

策略网络输出的频率控制步态快慢：频率越高，迈步越快。

## 六、老师可能提问的问题及参考回答

### Q1: 为什么选择 PPO 而不是其他 RL 算法？

**回答**：
PPO 是目前人形机器人运动控制领域最主流的算法，原因：
1. **训练稳定**：通过 clip 机制限制策略更新幅度，避免灾难性更新
2. **样本效率**：同一批数据可以重复训练多个 epoch（本项目用 5 个 epoch）
3. **实现简单**：相比 TRPO 不需要计算二阶导数（Hessian 矩阵）
4. **工业验证**：ETH Zurich、UC Berkeley 等团队的机器人 RL 工作大多基于 PPO

其他选择：SAC（更适合探索，但连续动作空间下不如 PPO 稳定）、TD3（确定性策略，不适合需要探索的任务）。

### Q2: 为什么用增量式动作而不是直接输出关节角度？

**回答**：
1. **平滑性**：直接输出角度容易产生跳变，增量式天然平滑
2. **训练稳定性**：增量范围小（每步 ±0.012 rad），梯度信号更温和
3. **物理合理性**：关节不可能瞬间跳到任意角度，增量式符合物理约束
4. **参考姿态**：可以在 ref_joint_pos 上微调，而不是从零学习所有关节角度

### Q3: 奖励函数为什么这么复杂？能不能简化？

**回答**：
奖励函数包含 25+ 项，每项解决一个具体问题：
- **速度跟踪**（前进、侧向、偏航）：核心任务目标
- **平衡**（身高、姿态）：保证不摔倒
- **步态质量**（抬脚、支撑、相位）：产生自然步态
- **平滑性**（动作、输出）：避免抖动
- **对称性**（力矩、步幅、角度）：防止瘸腿
- **能量效率**（关节速度、力矩）：减少能耗

简化会导致某些方面被忽略。例如去掉对称性奖励，机器人可能学会走路但一条腿拖着。各项奖励乘以 `balance_rew` 的设计确保了"站稳是前提"。

### Q4: 为什么用 4096 个并行环境？

**回答**：
1. **GPU 并行效率**：Isaac Gym 利用 GPU SIMD，4096 个环境的计算成本和 1 个差不多
2. **样本多样性**：每个环境可以有不同的初始状态、随机种子，提高数据多样性
3. **训练速度**：每轮收集 4096×24 = 98,304 条经验，远快于单环境
4. **mini-batch 效果**：更多数据让 mini-batch 的梯度估计更准确

### Q5: 什么是域随机化 (Domain Randomization)？为什么重要？

**回答**：
域随机化是在仿真中随机化物理参数（摩擦力、质量、PD 增益等），让策略在多种条件下都学会鲁棒控制。

**Sim-to-Real 问题**：仿真和真实世界总有差异。如果策略只在"完美"仿真中训练，到真实机器人上会失败。

本项目支持的随机化：
- 摩擦力随机化 `[0.65, 1.0]`
- 质量随机化 `[0.9, 1.2]`
- 惯性随机化 `[0.9, 1.2]`
- PD 增益随机化 `[0.9, 1.3]`
- 推力扰动（模拟被推）
- 观测延迟（模拟通信延迟）

### Q6: 步态相位调制器的作用是什么？

**回答**：
PhaseModulator 维护每条腿的相位 φ，由策略网络输出的频率控制：
- `φ ∈ [0, π)` → 支撑相：脚应着地承重
- `φ ∈ [π, 2π)` → 摆动相：脚应离地迈步

它的作用是：
1. **隐式步态时钟**：策略不需要直接控制每条腿何时抬起/放下，只需控制频率
2. **奖励计算依据**：用相位判断"该抬脚时是否抬了"
3. **观测信息**：sin(φ) 和 cos(φ) 作为观测输入，让策略知道当前步态阶段

### Q7: 为什么观测要加延迟？

**回答**：
真实机器人的传感器有延迟（IMU 约 5-10ms，编码器约 2-5ms）。在仿真中加入随机延迟 `[10, 20]` 步（约 10-20ms），让策略学会在有延迟的情况下控制，提高 Sim-to-Real 迁移效果。

### Q8: Actor 和 Critic 的输入为什么不同？

**回答**：
- **Actor 输入**（38维）：策略需要的信息——"我当前状态如何，目标是什么"
- **Critic 输入**：更完整的状态信息（包括真实速度、脚部位置等），用于准确估计状态价值

Critic 看到更多信息是因为它不需要输出动作，只需要评估"这个状态有多好"。在训练时 Critic 可以访问"上帝视角"信息，但 Actor 只能用实际可获取的传感器数据。

### Q9: γ (折扣因子) 和 λ (GAE 参数) 的作用？

**回答**：
- **γ = 0.993**：折扣因子，控制"多看重未来奖励"。越接近 1 越有远见，但方差越大。0.993 意味着大约考虑未来 1/(1-0.993) ≈ 143 步的奖励。
- **λ = 0.95**：GAE 参数，平衡 TD 和 Monte Carlo。λ=0 是纯 TD（低方差高偏差），λ=1 是纯 MC（高方差低偏差）。0.95 是常用折中。

### Q10: 为什么奖励要乘以 dt？

**回答**：
`reward × dt` 使得奖励与时间步长解耦。如果改变 dt（比如从 0.001 改为 0.002），奖励的物理含义不变（每秒获得的奖励相同），不需要重新调参。

### Q11: 项目中有哪些 Domain Randomization 技术？

**回答**：
1. **初始状态随机化**：初始姿态加噪声 ±0.05 rad，随机旋转 ±0.2 rad
2. **观测延迟随机化**：关节/角速度/姿态分别有不同延迟范围
3. **关节静态误差**：模拟编码器偏差
4. **观测噪声**：关节位置 0.01 rad，角速度 0.2 rad/s
5. **推力扰动**：每 3 秒施加随机推力（最大 100N）
6. **质量/惯性随机化**：在 epoch > 1000 后以 0.5% 概率触发

### Q12: 终止条件是怎么设计的？

**回答**：
[terminate()](env/tasks/locomotion_task.py#L676-L736) 包含多个终止条件：
1. **姿态超限**：Roll 或 Pitch > 1.6 rad（≈92°）→ 摔倒
2. **高度过低**：身体高度 < 0.4 m → 倒地
3. **关节超限**：多个关节触碰限位 → 危险姿态
4. **接触力异常**：非脚部身体接触地面 → 摔倒
5. **超时**：episode 达到最大时长

### Q13: 为什么需要 decimation？

**回答**：
策略运行在 100 Hz（每 10ms 决策一次），但物理仿真需要更高频率（1000 Hz）才能准确。decimation = 10 意味着：
- 策略每 10ms 输出一个目标
- PD 控制器在这个目标上保持 10 步（10ms），每步 1ms
- 这样既有足够快的控制频率，又不让策略负担太重

类比：你每秒做 100 个决策，但手臂肌肉每秒收到 1000 次神经信号。

### Q14: 你的项目和 ETH Zurich 的 legged_gym 有什么区别？

**回答**：
本项目参考了 legged_gym 的框架，但有以下改进：
1. **增量式动作**：legged_gym 通常用绝对角度，本项目用增量
2. **步态相位调制器**：legged_gym 用基于 CPG 的步态，本项目用策略网络直接控制频率
3. **丰富的奖励工程**：25+ 个奖励项，包括对称性奖励（治瘸腿）
4. **观测延迟模拟**：为 Sim-to-Real 做准备
5. **针对 H1 机器人**的特定调参

## 七、关键公式速查表

### PPO 策略损失
```
L_clip = -E[min(r_t × A_t, clip(r_t, 1-ε, 1+ε) × A_t)]
r_t = π_new(a|s) / π_old(a|s)
```

### GAE 优势估计
```
δ_t = r_t + γ × V(s_{t+1}) - V(s_t)
A_t = Σ_{l=0}^{∞} (γλ)^l × δ_{t+l}
```

### PD 控制器
```
τ = Kp × (q_target - q_actual) - Kd × dq/dt
```

### 步态相位
```
φ_{t+1} = (φ_t + 2π × f × dt) mod 2π
stance: φ ∈ [0, π),  swing: φ ∈ [π, 2π)
```

### scale_transform
```
output = clip(input, -1, 1)
output = (output + 1) / 2 × (high - low) + low
```

### 常见训练问题

1. **奖励不增长**：学习率太大/太小，检查 KL 散度
2. **机器人不走**：前进速度奖励权重太小，或命令范围太小
3. **机器人摔倒**：平衡奖励权重不足，或 PD 增益不合理
4. **瘸腿**：缺少对称性奖励
5. **动作抖动**：平滑性惩罚权重不足
